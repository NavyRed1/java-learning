# ADR-0008: Styling and UI stack for the first UI slice
Status: accepted (with a stated deviation). The master brief names Tailwind CSS, shadcn/ui and Lucide. This build environment has no network, so none of them (nor Next.js) could be installed or verified. Decision: tokens as CSS custom properties (`src/styles/tokens.css`), hand-written component CSS keyed on `data-*` attributes, an in-repo thin-line icon set, and small accessible primitives (`src/components/ui`). Components are plain React + TypeScript with no styling dependency, so adopting Tailwind later means mapping the tokens in a Tailwind `@theme` block, not rewriting components; Lucide icons can replace `Icon.tsx` behind the same `name` prop. Verified: the same components bundled with esbuild and exercised in real Chromium (19 end-to-end tests). Not verified here: `next dev/build` of `src/app/*` (thin wrapper files), type-checking TSX against `@types/react` (a shimmed partial check found no real errors). Fonts: Geist / Geist Mono named first with system fallbacks; load them with `next/font` in the Next app.
